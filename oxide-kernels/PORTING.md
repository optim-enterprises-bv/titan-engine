# Porting nvcc kernels to cuda-oxide (titan-engine)

Goal: replace every CUDA C kernel mistral.rs builds with a cuda-oxide (Rust) kernel that has the
**same entry name, the same parameter ABI and bit-identical output**. The callers (candle,
mistral.rs) must not be able to tell the difference. A port is done only when `kdiff` reports
0 differing bytes.

## Layout

- `reference/candle/*.ptx`: the exact PTX cargo built for candle-kernels (sm_120a). The oracle.
- `kdiff/`: host library. Loads reference + oxide PTX in one context, launches an entry by name in
  both with identical argument bytes and input buffers, compares output bytes.
- One crate per module, e.g. `candle-affine/` (the template: copy its Cargo.toml, rust-toolchain.toml,
  Cargo.lock and structure). `src/main.rs` holds the `#[cuda_module] mod kernels` and a `main()`
  that runs the differential gate and exits non-zero on any mismatch.

## Build and run (titan)

```
cd <crate>
export CUDA_OXIDE_BACKEND=$HOME/titan-engine/cuda-oxide-fast/librustc_codegen_cuda.so   # release + scan fix
systemd-run --user --scope -q -p MemoryMax=4G -p MemorySwapMax=0 env CARGO_BUILD_JOBS=2 \
  cargo oxide build --arch sm_120 > build.log 2>&1
target/release/<crate>     # prints "<module>: N launches, B bytes compared, 0 failing -> PASS"
```

titan has 30 GB RAM shared with other work. Always build under the systemd memory cap above.
Never run `pkill -f <pattern>` or `pgrep -f`: the pattern matches your own shell and kills it.

## Rules that decide bit-identity (learned the hard way)

1. **The SASS is the spec, not the source or the PTX.** Disassemble the reference:
   `ptxas -arch=sm_120a -O3 reference/candle/X.ptx -o /tmp/X.cubin` then
   `$CUDABIN/cuobjdump -sass -fun <entry> /tmp/X.cubin` (use `tools/cuobjdump` in this repo; titan's
   CUDA has no cuobjdump). nvcc's default `-fmad=true` and ptxas both fuse multiply+add into FMA:
   f32 `x*m+a` -> FFMA, and even separate PTX `mul.bf16`/`add.bf16` became one `HFMA2.BF16`.
   Rust never fuses, so write the fused op explicitly (`float::fma_rn_f32`, `bf16x2::fma_bf16x2`, ...).
   Conversely, where the SASS has separate FMUL/FADD, use separate `.rn` ops (they are never fused).
2. **candle-kernels are built WITHOUT --use_fast_math**: no `.ftz`, IEEE `div.rn`, libdevice math.
   (mistralrs-quant's kernels ARE fast-math: `.ftz`, approximate division. Check each library's flags.)
3. **Math functions**: Rust `f32::exp/sin/cos/tanh/powf/sqrt/ln/...` lower to libdevice `__nv_*`,
   the same code nvcc uses. For libdevice functions without a Rust method (erff, normcdff, ...)
   declare them: `#[device] unsafe extern "C" { fn __nv_erff(x: f32) -> f32; }` (libdevice is linked
   by the NVVM finalizer). Verify each one bit-matches.
4. **Integer width**: candle loops use `unsigned int` (u32) indices with `size_t` (u64) dims/strides.
   Reproduce the truncations exactly (see `get_strided_index` in candle-affine). Integer ops wrap.
5. **ABI**: raw pointers (`*const T` / `*mut T`) for arrays, `usize` for size_t, by-value scalars.
   f16/bf16 scalars are `u16` bit patterns (a `.u16` param is ABI-identical to nvcc's `.b8[2]`),
   fp8 is `u8`. Never use slices in kernel signatures (they become pointer+length pairs).
6. **Half types**: cuda-oxide has packed ops (`fma_f16x2`, `add_bf16x2`, `max_f16`, ...). A scalar op is
   lane 0 of the packed op (identical rounding). Conversions: `convert::cvt_f32_f16x2_lo`,
   `cvt_f16x2_f32(lo, hi)`, `cvt_bf16x2_f32`, fp8 `cvt_rn_f16x2_e4m3x2`, `cvt_rn_satfinite_e4m3x2_f32(lo, hi)`.
   bf16 -> f32 is an exact 16-bit shift.
7. **`#[kernel]` functions must be written out explicitly** (the `#[cuda_module]` scan does not see
   kernels generated by `macro_rules!`). Share logic via `#[inline(always)]` generic helpers with
   closures; functions that call thread/warp intrinsics directly need `#[device]` if not inlined into a kernel.
8. **Thread indices**: `thread::threadIdx_x/blockIdx_x/blockDim_x/gridDim_x` (and _y/_z).
   Shared memory: `SharedArray` (see titan-kernels-oxide). Warp shuffles: `warp::shuffle_*`.
   Reductions must reproduce the reference's exact order (shared-memory handoff order, butterfly vs
   shuffle-down, which lane writes).
9. **Test like an adversary**: random bit patterns (NaN, inf, +-0, denormals), contiguous and strided
   layouts (transposed, broadcast stride 0, size-1 dims, permuted), several grid/block shapes including a
   single block (grid-stride loops), in-place (null input) paths, odd sizes. Cover every entry in the
   reference module; list any entry you could not port and why.
10. **Exact instructions via `cuda_device::ptx_asm!`** (constraints h/r/l/f/d, `options(register_only)`;
    example in cuda-device/src/f32x2.rs). When the reference uses a `cvt` (or any op) cuda-oxide does not
    wrap, copy the instruction. Traps found in cast: C `(uint8_t)float` is `cvt.rzi.u32` then truncate
    (300.0 -> 44, not 255); u32->bf16 and f64->bf16/f16 round once, directly (via f32 double-rounds);
    `x + 0.0` is not a no-op (-0 -> +0). Mutation-test the gate: swap in a plausible wrong version and
    make sure it fails.
11. **64-bit integer division**: nvcc emits `if ((a|b) >> 32 == 0) div.u32 else div.s64`, so i64 `x / 0` with
    small non-negative x gives 0x00000000_FFFFFFFF, not -1. Reproduce the branch everywhere 64-bit `/` or `%` occurs.
12. **Half division is approximate even without fast-math**: bf16 `/` is `div.approx.f32` with a 0.25 rescale for
    |divisor| >= 2^126; f16 `/` is `__hdiv` (rcp.approx.ftz + mul + one fma correction for small non-zero results).
    Rare branches like the correction need targeted inputs: random data passed 6000 launches without it.
13. **Device asserts**: `cuda_device::gpu_assert!(cond, "literal")` emits a real `__assertfail` (error 710, same as
    candle's `assert()`); without a message it only traps. An assert poisons the context for all later launches, so
    mutation tests must stay in the valid input range.
14. Long entry lists: generate the explicit `#[kernel]` wrappers with a script between GENERATED markers
    (see candle-indexing/gen_kernels.py); the module scan still sees plain functions.
15. **f64 NaN propagation depends on operand order**: with two NaN inputs an f64 add/mul returns the second
    operand's NaN (quieted), and ptxas/LLVM choose the order per site. Where the reference can see two NaNs
    (fast_sum_f64, softmax_f64) pick the NaN explicitly per site from the SASS. f32/f16/bf16 return the canonical NaN.
    Test f64 with varied NaN payloads and signs.
16. Rust `f32::min/max` lower to compare+select (±0 order-dependent); the reference uses hardware `min`/`max`:
    emit those with `ptx_asm!`. `rsqrtf` is `rsqrt.approx.f32` even without fast-math; `1./x` is `rcp.rn`.
    cuda-oxide intrinsics can't be passed as fn values: wrap them in closures.
17. **Dynamic shared memory**: `cuda_device::DynamicSharedArray::<T>::get()` inside the `#[inline(always)]` helper
    (passing its pointer into a generic helper fails codegen: shared address space).
18. Mutation tests can pass by accident under stride symmetry: use unequal src/dst strides in wrap cases.
    Copying `candle-affine/target` into a new crate before its first build makes that build take seconds.
19. **f64 NaN payload order (measured)**: add/mul/max return the 2nd operand's NaN, then the 1st; fma: 2nd, then
    addend, then 1st. ptxas reorders operands vs the PTX (col2im1d PTX `add src, acc` is SASS `DADD acc, src`), so pick
    the NaN explicitly in SASS order (candle-conv `sass_dadd/sass_dfma/sass_dmax`). C `bool` params are `.u8`, any
    non-zero byte is true. Stride-0 inputs expose the 64-bit division bypass (`x/0` -> 0xffffffff).
20. **libdevice is not automatically bit-identical**: oxide's pipeline fused `a - q` inside `__nv_powf` where nvcc
    kept mul+sub (1-ulp diffs in ~3% of f32 results). Fix: transcribe nvcc's PTX with non-`.rn` `ptx_asm!` ops so
    ptxas fuses the same way. nvcc also fuses across the inlined libdevice boundary (`1 + expf(-x)` -> fma with expf's
    last multiply). Sweep all 2^32 f32 inputs for every libdevice-using entry (candle-unary `--exhaustive`, ~30 min).
21. NaN constants: `f32::from_bits(0x7FFFFFFF)` is canonicalised to 0x7FC00000 by the pipeline; build such NaNs with
    `ptx_asm!("mov.b32 ...")`. Half-type header helpers (hexp, hlog, __hdiv, ...) are best copied verbatim via ptx_asm!.
22. **FFI families (static libs)**: gate launcher-vs-launcher: link the real C launcher from the reference `.a`
    (build.rs: static lib + cudart + stdc++) and call it and the Rust launcher on identical inputs in the primary
    context. candle's libmoe.a is built with `--default-stream per-thread` (`_ptsz` symbols): stream 0 means the
    per-thread stream (handle 0x2). Unported-but-equivalent: integer prefix scans (one correct answer).
23. Half intrinsics `__hmul`/`__hsub` emit non-`.rn` `mul.f16`/`sub.f16`, which ptxas fuses (`dall*x - dmin*y` ->
    `fma(dall, x, -(dmin*y))`): mirror the SASS. WMMA copies cleanly as `wmma.*` via `ptx_asm!` (accumulator as 8
    `inout` operands). quantize_q8_1's `roundf` trap needs a targeted row (amax=127, values +-0.49999997).
    Upstream bug found: candle `moe_gemm_wmma` f16 output double-converts (`static_cast<half>(float_to_half(v))`).
24. Operand order in fused multiplies matters even from identical source: mmvq q8_0 is `fma(sumi*d0, d1, tmp)`
    (left to right). Index `row + threadIdx.x` into dst is u32 (IMAD.WIDE.U32) with an unsigned guard. Search the
    host for inputs that hit rare branches (rz-vs-rn roundf) instead of hoping random data finds them.
25. C sums of products become fma chains in the PTX and which product fuses varies per expression: read the PTX
    for every chain (ptxas only adds fusions). `a*b - c*d` -> `fma(a, b, -(c*d))`; `acc += x*y` -> `fma(x, y, acc)`.
26. `#[unroll]` silently skips loops whose bound is a local or struct field: use consts (grep build.log for
    "not unrolled"). `#[device]` fns are real calls, so pointer args lose their address space (generic ld/st,
    1.5-2.7x slower): use `ld.global.nc`/`st.shared` via ptx_asm! + `cvta_generic_to_shared_u32`.
27. **Keep mutation-test backups inside your own crate** (e.g. `<crate>/.mut/`, gitignored): the session scratchpad is
    shared between parallel agents and a restore once copied another agent's main.rs into the wrong crate.
    Upstream bugs reproduced faithfully: candle indexed_moe_forward q8_0 sizes experts with 256 values/block (not 32).
28. **Fast-math lowerings (mistralrs-quant)**: `a/b` = rcp.approx.ftz + mul.ftz; `x/const` = mul by reciprocal;
    `expf(x)` = ex2.approx.ftz(x*log2e) (sign folded into the constant for expf(-x)); `tanhf` = tanh.approx;
    fminf/fmaxf = min/max.ftz; fabsf = abs.ftz (-0 -> +0); `x * -1.0f` = neg.ftz; roundf = copysign(0.5) +
    add.rz.ftz + cvt.rzi; f32 `!= 0` = setp.neu.ftz (denormals count as zero); red.add.f32 is always ftz.
    One expression can contract differently per dtype (rotary f16/bf16 vs f32).
29. **Nondeterministic references**: outputs whose order comes from atomics are compared after sorting within each
    segment (the reference itself varied run to run); float atomics are tested with one non-zero contributor.
    `#if __CUDA_ARCH__` in host launchers can compile to stubs: check the host object, not just the cubin.
30. Fast-math also flushes f32 compares (FSETP.*.FTZ) and swaps log1pf for libdevice's ftz variant; `a / b + c`
    fuses into one FFMA with the reciprocal; which product fuses can differ per template instance (ssm c_factor 1 vs
    2/4/8): read every instance's SASS. Closures capturing a shared-memory pointer fail codegen: inline instead.
31. Gates should detect reference races: on mismatch, rerun the C launcher on fresh copies and flag self-disagreement.
    Upstream bugs reproduced: vllm `to_float(half)` / `from_float` integer<->half reinterpretation (moe_gemv, moe_gemm).
32. **Gate streams**: `CudaContext::new_stream()` is non-blocking; an upload on one stream can still be in flight when
    a kernel on another starts (random mismatches, or both sides reading stale bytes). Upload and launch on the same
    stream, or `cuCtxSynchronize()` after uploads.
33. `#[unroll]` only works in `#[kernel]`/`#[device]` fns; in `#[inline(always)]` helpers put
    `cuda_device::thread::__unroll_config::<0>();` first in the loop. Bounds must be MIR literals / associated consts.
    Unroll is refused above 65,536 cloned ops (arrays then spill to local memory): move the body into an
    `#[inline(always)]` fn. Runtime-indexed arrays spill too: use if/else selects.
34. References that read past the tensor (mmq: up to 7 blocks past the last row) make the output depend on tail
    bytes: give both sides identical tail bytes. Integer mma results are exact; only the float epilogue must match.
35. `__byte_perm` is not plain `prmt.b32`: PTX prmt sign-extends when bit 3 of a selector nibble is set; mask the
    selector with `& 0x7777`. Unrounded fast-math `add.ftz`/`mul.ftz` get fused by ptxas: use `add.rn.ftz`/`mul.rn.ftz`
    where the SASS has separate FADD/FMUL. Fast-math folds `x * 1.0f` (no flush) and turns `* -1.0f` into
    `add.ftz(-x, -0)`.
36. Random data hides accumulation-order bugs when products are exact in f32: use cancelling data (second half = negated
    first half) so the result is pure rounding residue. CUTLASS 2.x processes the K residue tile first.
    Shared-memory pointers cannot be captured by closures: launder through usize; use generics, not `&dyn Fn`.
37. **Rebuild the reference PTX** when only SASS was shipped: nvcc 13.3 `-ccbin g++-15` with the crate's build.rs
    flags reproduced SASS identical to the reference cubins (paged-attn), giving exact PTX to read contractions from.
38. **Build time**: cuda-oxide's detect.rs scans every `mul.`/`add.`/`fma.` in the LLVM text for "f32x2"; appending
    `//\t\x0b\x0c\r\n` to those `ptx_asm!` strings cut a 378-kernel build from 30 min to ~2 min (PTX unchanged
    apart from the comment).
39. Upstream quirks reproduced: paged-attn alibi bias uses unsigned `(u32)(token_idx - context_len + 1)`; fp8->f32
    rounding depends on vector width (vLLM quant_utils). CUDA 13 reports invalid launch configs as error 1.
40. FlashInfer quirks reproduced: `math::inf` is 5e4 (masked logits -5e4; fully-masked prefixes add exp(0)=1 to the
    sum); merges fold into the initialised state (`d = fma(d_other, e2, e1)`, `o = fma(e1, 0, o_other*e2)`); the merge
    rounds normalised partials to the output dtype in shared memory; MLA scales by sm_scale*log2e before the shuffle
    reduction, decode after. Fast-division page sizes (7, 21, ...) take an extra-add branch: test them.
41. Kernels no launcher reaches can still be gated: pack the by-value Params struct from the reference PTX's offsets
    and launch straight from the reference cubin. Halving `while off > 0` loops are not recognised as counted: use
    `k < N` with `16 >> k`.
42. mistralrs-quant mmvq/mmq vs candle: all f32 ops `.ftz`; `amax/127` -> mul.ftz by 0x3c010204; `1/d_inv` ->
    rcp.approx.ftz; mmvq b_size 1 uses 8 warps x 2 rows (candle 4 x 1); fused-GLU output is
    `(dst_t)act((float)(dst_t)gate) * (dst_t)up` multiplied in the output type; mmq adds llama.cpp fastdiv (pass the
    uint3 as 3 x u32), MoE ids_dst/expert_bounds (reads up to mmq_x past the end: identical tail bytes), and a
    tile-efficiency grid. Stream-k tmp_fixup rows past the tensor are nondeterministic in the reference: mask exactly
    those rows and assert C-vs-C equality elsewhere.
43. **Performance: keep per-thread arrays in registers.** An array stays in registers only if it is sized by a
    const generic (`[f32; KD]`) and indexed only by constants inside fully unrolled loops; a runtime-bounded loop sends it
    to local memory (this cost the GDN decode kernel 3.7x and the tiled prefill 5x vs nvcc). Derived unroll bounds need
    an associated const. Rewrite `for (j = tid; j < N; j += S)` as `c in 0..ceil(N/S)` with `if tid + c*S < N`.
    `||`/`&&` over `ptx_asm!` predicates become branches: use `|`/`&` so they become selects. Replace runtime-indexed
    writes with a select chain over the unrolled indices. Check the SASS for LDL/STL inside the hot loop, not the stack size.
    Profile end to end with nsys (no counter permission needed) before guessing; `sudo ncu` for counters.
44. `gen` is a reserved keyword in edition 2024: don't name a gate helper `gen`.
45. **by-value structs / uint3 params (llama.cpp)**: pass the fields as scalar params with the same param-space offsets
    (`ggml_cuda_mm_fusion_args_device` = 5 x u64 + u32 + f32 at offset 24; `uint3` = 3 x u32) and launch BOTH sides from
    one packed buffer (cuLaunchKernel `extra` = CU_LAUNCH_PARAM_BUFFER_POINTER), see q1_0/src/gate.rs. llama.cpp's CUDA is
    `-use_fast_math` (all f32 ops .ftz); its reference cubins are rebuilt from compile_commands.json (q1_0/ref/nvcc_*.sh)
    and must be SASS-identical to libggml-cuda.so (q1_0/ref/sass_cmp.py) before gating.
46. **Fast-math PTX without `.rn` is a fusion licence**: llama.cpp's `mul.ftz(mul.ftz(d, q), 0.5)` (mxfp4 dequantize)
    is one `FMUL.FTZ.D2` in SASS, which does not flush the halved result (2^-127 survives); `mul.rn.ftz` twice
    flushes it. Copy the reference's un-rounded `mul.ftz` (mxfp4 `mulf`) where the SASS fused. sm_120a-only
    instructions (`cvt.rn.bf16x2.ue8m0x2`) need `cargo oxide build --arch sm_120a` (the PTX then says sm_120a).
47. **Activation quantizers are part of "bit-identical"**: candle's `quantize_q8_1` (no fast-math: `div.rn` for
    `amax/127` and `x/d`) is not llama.cpp's (`div.approx.ftz` twice); on real activations ~1-3% of Q8_1 blocks differ,
    which is enough to change greedy text. q1_0 ships llama.cpp's quantizers (f16/bf16 inputs widened exactly first).
    MMQ ports: the reference's `const __restrict__` loads are `LDG.E.CONSTANT`; `ld.global.nc` via ptx_asm! closed most of
    a 3-12% gap. Embedded PTX is JIT-compiled at first use (the Q1_0 MMQ module: ~3 s): warm up before timing, and split
    big modules (q1_0/export_ptx.py) so decode does not wait for the prefill kernels.
48. **Check which MMQ config the target arch compiles, not the one the source shows first**: llama.cpp built for sm_120a
    (BLACKWELL_MMA_AVAILABLE, compile_commands.json `compute_120a`) runs MXFP4 / NVFP4 through mmq-config-blackwell.cuh:
    activations are quantized to FP4 (`quantize_mmq_mxfp4` / `quantize_mmq_nvfp4` into block_fp4_mmq, 256 values per 144
    bytes; NVFP4 also writes a per-column f32 scale that the write-back multiplies in), weights are copied raw into SRAM, and
    the product is `mma.sync ... kind::mxf4[nvf4].block_scale` m16n8k64 with K_vram 512, not the q8_1 path. IQ4_NL keeps the
    ampere config (q8_1 D4, s8 MMA). The block-scaled MMA is exact hardware: only the epilogue (`add.ftz(C, sum)`, NVFP4
    `mul.ftz(y_scale, sum)`) and the quantizers need float care (lg2.approx + cvt.rni for E8M0, rcp.rn.ftz, cvt.rn.satfinite
    .e2m1x2 / .e4m3x2 with the hi operand first, setp.*.ftz compares). See fmt_mmq.
49. **Rule out equivalent mutations before hunting for inputs**: quantize_mmq_nvfp4's SASS fuses `|v| - |q|*2s` into FFMA,
    but 2s*|q| has at most 6 significant bits (ue4m3 x e2m1), so fused and unfused are bit-equal (a 5.2M-row hunt found
    nothing, as it must). Same for rcp.rn vs rcp.approx of an E8M0 (power-of-two) scale and for the stream-k fixup's
    `% blocks_per_iter` (it only moves kbc inside a tile). Mirror the SASS anyway, but mutate something that changes values
    (rounding mode, a `<` tie-break turned `<=`, the scale row, a dropped y_scale, a fixup that overwrites).
