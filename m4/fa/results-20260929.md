- The KV-copy agent's diagnosis holds, but the bigger half is the softmax: candle's `softmax_last_dim` gives each
  of the 16 rows one block, 372 us at 28k keys.

## Kernel design (oxide-kernels/flash-decode, mistralrs-core/src/attention/flash_decode.rs)

- `flash_decode_split_g{8,16,24}`: grid (ceil(kv/chunk), kv_heads), 256 threads. A block takes one KV head and one
  `chunk` of keys (default 256, `TITAN_ATTN_FLASH_CHUNK`) for **all G = 8 query heads x rows** of that head, in
  128-key tiles:
  - phase A: 2 threads per key, each 16-byte `ld.global.nc` chunks of the K row, dot with f32 Q (pre-scaled, in
    shared memory, broadcast reads) for every query, pair-sum by shuffle;
  - online softmax per query per tile (warp butterfly max/sum + shared), running max offset by llama.cpp's
    FATTN_KQ_MAX_OFFSET, fast-math expf;
  - phase B: thread = output dim, V read once per key, f32 accumulation for all queries.
  - writes an unnormalised f32 partial + (max, sum) per query and chunk.
- `flash_decode_combine`: grid (heads, rows), merges a row's chunks in chunk order (flash_attn_combine_results), bf16.
- Row i sees keys < past + i + 1. **Row-exact**: tiles/chunks are fixed from key 0, masked keys add exact zeros,
  untouched state is scaled by exactly 1, every reduction is in a fixed order over one query's values, and all f32
  ops are explicit PTX (no per-instance contraction). So a verify row equals the decode step it replaces bit for bit;
  MTP=2 output = MTP off output also above the threshold.
- Wiring: `run_attention_noflash` (single CUDA decode row, no mask, bf16, d256, GQA <= 24) and
  `decode_rows_attend` (the MTP verify rows: one call for every row at or above the threshold, earlier rows keep
  the per-row path); `mtp_forward` catch-up rows (m > 1) above the threshold go through the rows path too.
  Env: `TITAN_ATTN_FLASH` (default on), `TITAN_ATTN_FLASH_MIN` (default **1024** keys), `TITAN_ATTN_FLASH_CHUNK`
  (256). `TITAN_ATTN_F32REF=1` is a debug f32 reference path.
- Graphs: runs eager between segments like the old attention. It is **not capture-safe as written** (kv_total by
  value, partials allocated per call); with kv_total from a device buffer and a persistent workspace it could move
  inside the graph segments.

Kernel gate (`oxide-gate.log`): 2.68M outputs vs an f64 softmax reference (bound 2^-8 rel + 2^-12), worst 0.89 of
the bound; 780/780 rows of 2-3-row launches bit-identical to 1-row launches at each row's key count (L = 1..28001,
chunk 128/256/512, n_rep 8/4, G instances 8/16/24; cache past kv_total filled with NaN); mutation (neighbouring key
count) 620/620 caught. Timing (16 heads, 2 KV heads): 28k keys, 3 rows: 173-183 us (vs ~2.3 ms for the old verify
span); 1 row 115-119 us; 2.1k, 3 rows, chunk 128: 26 us.

## Gates

**(a)** final binary (min 1024): 35B 40/40 vs q35-prof (MTP off), MTP=2 40/40 vs h-off (also 40/40 + 40/40 on the
first build with min 4096). The gate prompts are < 400 keys, so they take the old path.

**(b)** 64 greedy tokens with top-5 logprobs, MTP=2, prefix cache off (`out/lp-*.jsonl`, cmp_lp.py; KL over positions
up to and including the first divergence):

| comparison | 13k (10.9k tok) | 28k (27.7k tok) |
|---|---|---|
| yardstick: old, prefill chunk 256 vs 512 | identical, 64/64, KL 0.0011 | identical, 64/64, KL 0.0021 |
| new vs old (cuBLASLt) | identical, 64/64, KL 0.0006 | diverges at token 5, top-1 5/6, KL 0.134 |
| **old vs f32 reference** | identical, KL 0.0005 | diverges at token 5, top-1 5/6, KL 0.026 |
| **new vs f32 reference** | identical, KL 0.0002 | **identical, 64/64, KL 0.0045** |
| old chunk 256 vs f32 reference | identical, KL 0.0012 | diverges at 5, KL 0.0078 |
| new MTP off vs new MTP=2 | identical, logprobs equal | identical, logprobs equal |

The 28k divergence is the old path's error: cuBLASLt rounds the scores and probabilities to bf16. Against an f32
reference (`TITAN_ATTN_F32REF=1`: the grouped path on f32 copies) the new kernel keeps the text and sits closer than
the chunk-size yardstick; the old path is the one that flips token 5 (top-2 probabilities 0.70 / 0.29 on the old path, 0.14 / 0.85 on the new; the f32 reference has a near-tie, 0.56 / 0.44, with the new path's argmax).

- Short-context rate (bench e2e, eval8): ~107 tok/s MTP=2, ~87 MTP off. 28k is at or above it with MTP=2 and 4% under
  with MTP off: target (within ~15%) met.
- Threshold: flash beats nocopy at 2.1k and 3.3k (min 1024 run: 110.7 / 109.6 vs 96.9 / 94.0), hence 1024.
  Chunk 512 was no better than 256 (113.3 vs 114.2 at 28k).
- Profile of the new kernel at 28k (first build, min 4096): attention 1.01 ms/token (MTP=2, was 9.15), 1.29 ms
  (off, was 7.28), 16% of GPU busy.

## Deploy (for the main session)

1. Build b7f5c6e98 (mr-fa, nvcc-free), run `bench/window.sh` on it, compare 13k prefill with the deployed binary.
2. No unit change: flash-decode is on by default from 1024 keys. `TITAN_ATTN_FLASH=0` restores the old decode attention.
3. Follow-ups: the kernel is FMA-bound at 3 rows (~330 GB/s of K+V at 28k, 1 row ~500 GB/s); an MMA (fattn-mma) phase A
   and moving the pair inside the graph segments (device-side kv_total, persistent workspace) are the next levers.
